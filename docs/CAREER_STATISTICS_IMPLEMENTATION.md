# Статистика карьеры, сезона и тренера — статус реализации

Дата: 29 октября 2026. Репозиторий: `penzinvv/futbolny-trener-nachalo`.

## Реализовано в репозитории
- В `data/league.json` каждому из 120 стартовых игроков назначен постоянный UUID `careerId`.
- В `src/app.js` создаются и сохраняются постоянные ID пользовательского тренера и его команды.
- В кабинете тренера есть обзор матчей, результатов и забитых/пропущенных голов на основе коллекции `careerHistory`.
- Локальная структура `careerHistory` резервирует список официальных матчей и архив сезонов.
- В `supabase/migrations/202610290001_career_season_statistics.sql` подготовлена реляционная схема для серверной статистики и истории.

## Что ещё НЕ реализовано
- Нельзя сохранять официальные результаты на сервер: найденный Supabase-проект `ne-po-spisku` относится к другой игре и не должен изменяться этой миграцией.
- Текущий `test-match.html` — симулятор для проверки движка. Он не создаёт официальный результат и не должен влиять на таблицы, рейтинг или карьеру.
- Пока нет авторитетного официального календаря, завершения сезона, защищённой функции сохранения матча и серверной авторизации тренера, статистика в кабинете остаётся нулевой/локальной.
- Возрастная архивация в 21 год и полноценный интерфейс истории игрока/клубов требуют интеграции с настоящими сущностями и матчевыми протоколами.

## Правила постоянных идентификаторов
- Не использовать имя игрока как первичный ключ.
- При трансфере переносить исходный `careerId` вместе с игроком.
- Если игроку меняют имя, его ID не меняется.
- Архив игрока после 21 года не удаляется.
- Клубные и сезонные показатели всегда хранятся с привязкой к команде и сезону.
- Один официальный матч может быть учтён только один раз по уникальному `source_match_key`.
- Не записывать результат из тестовой страницы как официальный.

## Схема базы данных
Миграция создаёт таблицы тренеров, команд, сезонов, игроков, матчей, событий матча, статистики игроков/тренеров/команд по сезонам, истории командных переходов и достижений. RLS включён на всех новых таблицах; запись должна идти через доверенный серверный слой, а не из браузера с публичным ключом.

## Порядок безопасного запуска
1. Создать/подтвердить отдельный Supabase-проект именно для футбольного тренера.
2. Проверить владельца/авторизацию и способ восстановления сохранения.
3. Применить миграцию в этот проект, не в `ne-po-spisku`.
4. Разработать защищённую серверную функцию сохранения официального матча с транзакцией и защитой от повторной отправки.
5. Подключить официальный движок и календарь к этой функции.
6. Добавить агрегирование и сверку статистики из матчевых протоколов.
7. Реализовать архив сезонов, историю игрока по клубам и уход игрока из активного состава в 21 год.
8. Проверить трансфер, повторную отправку матча, автогол, замену, новый сезон и архивирование игрока.

## Важное замечание
Миграция в репозитории — это SQL-файл, а не уже изменённая база данных. Её не применяли к Supabase, чтобы не повредить существующий проект другой игры. Изменения GitHub также не означают, что сайт уже опубликован на Netlify.

- Нельзя объявлять облачное сохранение завершённым до проверки записи и последующего чтения реальных данных из Supabase.

## Проверка инструментами 29 октября 2026 — продолжение

### Подтверждено напрямую через Supabase
- Проект `qfkekaipmbtzxtuspjqv` активен и использует PostgreSQL 17.
- Все 13 таблиц карьеры существуют; RLS включён.
- Активны Edge Functions `career-health` (версия 1) и `career-api` (версия 2); обе требуют JWT.
- На момент контрольного запроса счётчики были нулевыми: seasons=0, coaches=0, teams=0, players=0, active_roster_links=0. Значит, успешную облачную инициализацию пока нельзя утверждать.
- Политик RLS на таблицах public нет. Это блокирует прямой доступ через клиентские роли, но не мешает серверной функции с service-role при условии строгой проверки пользователя. Не добавлять широкие политики.

### Исправление career-api
- Ключи стартовых игроков теперь изолированы по ID пользователя: `userId:careerId`. Это устраняет риск, что bootstrap другого аккаунта обновит запись того же стартового игрока.
- Добавлена проверка ровно 10 стартовых игроков, непустых уникальных имён и навыков от 0 до 100.
- Обновлённый исходник сохранён в `supabase/functions/career-api/index.ts`; функция развёрнута в Supabase как версия 2.
- Код синхронизирован с GitHub; commit: `369496957cd273da7afed0a0774e7fe220187525`.
